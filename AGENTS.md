# AGENTS.md

Instructions for AI coding agents (and humans) working on Kosmo. This is the single source of truth: `CLAUDE.md` is only `@AGENTS.md` and `.cursor/rules/kosmo.mdc` points here. Put new rules in this file, not in those.

## Project

Kosmo is a web app for voice calls and text chat with AI astrologer personas, in English or Hinglish. Users sign up, enter birth details once, then pick one of 24 personas. Every persona is an AI and the UI says so everywhere.

Live at https://kosmo-ai.vercel.app. Repo: https://github.com/tarunkauxhik/kosmo.

## Commands

```bash
pnpm dev                 # Next.js + Convex dev together
pnpm dev:web             # Next.js only
pnpm dev:convex          # Convex only (pushes functions to the dev deployment, regenerates convex/_generated)
pnpm build && pnpm start # production build and server
pnpm lint                # ESLint
pnpm typecheck           # tsc for the app and for convex/
pnpm format              # Prettier (write)
pnpm seed                # upsert personas from lib/constants.ts into Convex (--prod for production)
pnpm emoji:fetch         # download emoji images for EMOJI_SET
pnpm generate:portraits  # generate missing persona portraits with Gemini (needs GEMINI_API_KEY)
pnpm dev:voice           # optional Pipecat agent (needs uv)
```

Development happens on Windows: keep scripts cross-platform (Node scripts, no bash-only syntax in `package.json`).

## Environment and deployment

- Next.js reads `.env.local` locally and the Vercel project env in production. LLM keys and Better Auth settings live on the Convex deployment (`npx convex env set ...`) and never in `.env.local` or Vercel.
- Full table: [docs/ARCHITECTURE.md#environment-variables](docs/ARCHITECTURE.md#environment-variables). Never print, log or commit secret values.
- Web: pushing to `main` deploys to Vercel. Convex is **not** deployed by Vercel: any change under `convex/` needs `npx convex deploy` for production, and `pnpm seed --prod` after editing personas. Details: [docs/ARCHITECTURE.md#deployment](docs/ARCHITECTURE.md#deployment).
- Ask before changing env vars or deploy settings.
- For a local backend without an account: `CONVEX_AGENT_MODE=anonymous npx convex dev`.

## Coding conventions

- TypeScript strict. No `any` unless a library forces it, and then with a comment.
- Server Components by default. Add `"use client"` only for state, effects or browser APIs, and keep client components small and low in the tree.
- Public pages must stay static: nothing in `app/(public)` or the root layout may read cookies, headers or Convex at request time. Public persona data comes from `lib/constants.ts`; the dashboard reads the same personas from Convex (seeded from that file).
- Signed-in providers (Convex client, auth, toasts) live in `app/(dashboard)/layout.tsx` via `AppProviders`, so public pages ship none of that JavaScript.
- Imports use the `@/` alias. Components are PascalCase files, hooks `useX.ts`, lib modules lowercase.
- Prettier: 4 spaces (2 for JSON/YAML), 120 columns (`.prettierrc.json`). Run `pnpm format` before finishing.
- Comments explain why, not what. No commented-out code, no TODOs without an owner.
- Smallest correct change. No new dependencies without asking, no speculative abstractions.

### Convex

- Read `convex/_generated/ai/guidelines.md` before writing Convex code. It overrides older habits.
- Every public query/mutation/action declares `args` validators and checks the caller with `requireIdentity` / `requireUser` from `convex/lib/users.ts`. Users only ever see their own rows.
- Writes that the browser must not be able to forge (assistant messages, bot call turns, seeding) are `internalMutation`s called from actions.
- Ids that arrive from the browser (for example a storage id) are checked for ownership before use.
- Bounded reads: use indexes and `.take(n)`, not `.collect()` on growing tables.
- Every call that spends money on a third-party API goes through the rate limiter (`convex/lib/rateLimits.ts`). Next.js API routes call `guardRequest()` in `lib/api-guard.ts`, which checks the session and consumes a limit in Convex.
- Do not run `npx convex ai-files install` or `update`: they re-add a Convex block to `CLAUDE.md`/`AGENTS.md` and reinstall all ~30 Convex skills into `.claude/skills` and `.agents/skills`. If you need fresh guidelines, run it, then revert everything except `convex/_generated/ai/`.

### Security

- Never expose a secret to the browser. Only `NEXT_PUBLIC_*` values reach the client, and none of those are secrets. LLM keys live on the Convex deployment; speech keys stay in Next.js route handlers.
- The browser never talks to an LLM. Prompts are built on the server (`convex/lib/prompts.ts`) from the persona record and the stored profile, never from text the client sends as instructions.
- Browser-facing third-party connections need a CSP entry in `next.config.ts` (`connect-src`). Add the host there when you add a service.
- Redirect targets from `?next=` go through `safeNext()` (same-site relative paths only).
- Do not log user content or API error bodies that may contain configuration.

## UI rules

Tokens, scales and the reasons behind them: [docs/DESIGN.md](docs/DESIGN.md).

- Use the tokens in `app/globals.css` (`bg-background`, `text-muted-foreground`, `bg-brand`, `shadow-surface`, ...). No raw hex in components except the documented End-call red.
- Light and dark themes must both work. Theme state is in `lib/theme.ts`; the toggle is `components/ThemeToggle.tsx`. Check new UI in both.
- One font: Geist (`font-sans`), weights 400 to 600. Do not add fonts.
- Details: concentric radii, optical alignment, `tabular-nums` for changing numbers, shadows for elevation and borders for structure, 0.96 scale on press, `text-wrap: balance` on headings, no layout shift.
- Motion: CSS only (no motion library), 150 to 250 ms, `--ease-out-strong`, transform/opacity/colour only, never `transition: all`. Respect `prefers-reduced-motion`.
- Build on shadcn components in `components/ui`. Add new ones with the shadcn CLI or MCP, then restyle to the tokens.
- Emoji go through `<Emoji>` (`components/Emoji.tsx`), never as raw characters in UI. Add new ones to `USED_EMOJI` in `lib/emoji.ts` and run `pnpm emoji:fetch`.
- Hit targets at least 40 px (44 px for primary mobile controls). Every interactive element needs a visible focus state.

## Performance and SEO budgets

- Lighthouse on public pages, mobile: Performance 95+, Accessibility, Best Practices and SEO 100. Desktop 100 across the board.
- CLS 0. The hero headline (LCP element) is never animated.
- Public pages stay prerendered (`○` or `●` in the build output). Check after every change to `app/(public)` or the root layout.
- Each indexable page uses `pageMetadata()` from `lib/seo.ts` (canonical, OG, X card). Persona pages carry JSON-LD.
- `/dashboard/*` and the auth pages are `noindex` and excluded from the sitemap.
- Do not add client-side dependencies to public pages without measuring the bundle.

## AI honesty

- Every persona is labelled as an AI persona wherever it appears (`<AiBadge>`), and portraits say they are AI-generated in alt text.
- No fake reviews, ratings, user counts, testimonials, "verified" badges or claims of real-world credentials or accuracy.
- Keep the "reflection, not medical, legal or financial advice" notes on the landing page, footer, sidebar, composer and persona pages.
- Personas must say they are an AI when asked. Do not change prompts to deny it.

## Definition of done

1. `pnpm lint` and `pnpm typecheck` pass with no new warnings.
2. `pnpm build` passes and public routes are still static.
3. `pnpm format` leaves no diff.
4. UI changes: check the affected screens at 390 px and 1440 px in light and dark themes (screenshots if you can), including empty, loading and error states.
5. Public page changes: run Lighthouse (mobile) and stay within the budgets above.
6. Changes under `convex/`: say that production needs `npx convex deploy` (and `pnpm seed --prod` for persona edits).
7. Update the docs in `docs/` when you change architecture, env vars, tokens or a decision.
